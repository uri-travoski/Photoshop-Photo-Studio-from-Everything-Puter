# PSD compatibility audit

The source set is the 50 documents in `/Users/nj/Downloads/testing/psd/`, downloaded from the MIT-licensed psd-tools sample collection. Audit progress is recorded here so a pending semantic or interoperability issue is not mistaken for a passing screenshot. The audit is paused at the user's request after the current gradient milestone is committed and pushed to [PR #9](https://github.com/HeyPuter/everything/pull/9). Files 01–06 have production import/render/native/PSD round-trip evidence. File 07 is under investigation: its masked solid fill, original solid-stroked polygon, native-grid patterned ellipse and a dash-only reduction of its gradient polygon have editable round-trip evidence, while the full document still requires unsupported features. The semantic and interoperability gaps below remain open.

## Validation tools

`npm run psd:audit -- <directory> [file-count] [output-directory]` visits documents in alphabetical order. It runs the production importer, GPU compositor, project serializer, PSD exporter, and importer again. It compares decoded source layers with uploaded source textures, records layer properties and geometry, and writes diagnostic PNGs and exported PSDs. Generated outputs are local, ignored files under `test-results/psd-audit/`. Set `PHOTO_EDITOR_AUDIT_BACKEND=webgl` to repeat the production audit on WebGL2. High-depth comparisons use native typed source/composite samples; diagnostic PNGs use color-managed SDR display samples.

Pixel differences from embedded composites are diagnostic only. The composites may be stale or use different integer rounding; editable layer operations must be investigated independently.

For 8-bit shapes with supported RGB strokes, primary pixel masks or native-grid pattern fills, the audit also isolates the layer, exercises production import/render/native/PSD round trips, and writes an independent shape export. Supported solid and native-grid pattern fills retain their original paths, definitions and style. If a fill is unsupported, the diagnostic explicitly disables it and supplies an unused solid fill; original path and stroke parameters remain intact. The report identifies this stroke-only reduction. These reductions do not certify the original fill or full document.

Validation relies on independent decoding: psd-tools is available in a temporary Python environment and verifies exported channel planes, resource records, resolution and hierarchy. This does not establish rendering or editing behavior in other PSD applications; those checks remain unverified.

## Native pattern-resource parsing

Investigation of file 07's remaining pattern fill exposed a resource-decoder gap. The pinned decoder drops sheet alpha, rejects ZIP and high-depth pattern channels, and eagerly allocates every embedded tile. Controlled independently generated resources reproduce those failures. Production import now indexes the original `Patt`/`Pat2`/`Pat3` records without converting or allocating their pixels. This preserves the size point, IDs/names, palette, VMAL/channel rectangles, written-but-empty slots, compression and native payload bytes. The vertical/horizontal point represents size, not tile origin. Unsupported color modes remain indexed and retained in opaque native/PSD metadata.

On-demand decoding supports native 8/16/32-bit RGB and grayscale, plus 8-bit indexed palettes, using RAW, PackBits RLE, ZIP and ZIP prediction. RLE respects each scanline and the pattern format's 16-bit row lengths in both PSD and PSB. Prediction uses byte deltas, big-endian ushort deltas or float byte planes as appropriate. Separate sheet alpha preserves straight RGB, HDR, negative zero and subnormal samples. Each plane uses its original rectangle; a missing sheet-alpha plane is opaque. Written planes occupy their own rectangle in a zero-initialized channel canvas. User masks, mixed channel depths and bitmap/CMYK/Lab conversion are rejected explicitly by the tile decoder while their original resources remain retained. Pattern-fill sampling, color handling, geometry and editing remain unimplemented. They are not approximated or certified by this codec work.

Length-delimited parsing bounds index allocation and validates nested sections. Tile dimensions and decoded-memory budgets are checked before pixel allocation. Streaming ZIP output is bounded by declared channel dimensions, with truncated, trailing, concatenated or oversized streams rejected. Malformed pattern blocks are reported even when the dependency would suppress tagged-block errors. Scoped dispatch uses the same pinned CommonJS parser graph as the mask/stroke adapters; the package's separate browser ESM graph cannot receive those overrides. Pako 2.1.0 was already an ag-psd dependency and is now declared directly (MIT/Zlib) for bounded streaming decoding. Lazy dependencies remain prebundled to avoid development reloads during first import.

Original psd-tools fixtures vary channel depth, compression, alpha, palette and rectangle layouts. Regression coverage includes empty slots, typed-array offsets, repeated decoding, invalid float/alpha samples, nested lengths, index limits, PackBits no-ops, ZIP expansion bounds and oversized unreferenced tiles that require no pixel allocation. Production browser round trips vary document depth, PSD/PSB input, all three resource keys, geometry edits and GPU backend. ## Native pattern asset resolution

Preserving the original resource bytes did not provide a way to retrieve a native definition by ID from saved document metadata.
